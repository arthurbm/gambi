# v0.7.0 release draft

Status: pending. Run the release workflow only from `main` after PR #81 merges.

## Release notes

Gambi 0.7.0 lets a participant share a local coding harness as well as an OpenAI-compatible model endpoint.

- `gambi join --harness opencode|claude-code|codex` starts the selected local ACP process in a Gambi workspace. The harness keeps its existing local login.
- ACP v1 messages and versioned workspace artifacts cross the participant-opened tunnel. The hub validates the Gambi frame and relays the ACP message without interpreting its JSON-RPC payload.
- `client.harness.attach()` gives management clients a typed WebSocket channel for harness messages, session control, status, and artifacts.
- Room SSE adds `harness.session.opened`, `harness.session.closed`, and `harness.artifact`. Artifact events contain metadata only.

The protocol and architecture decision is recorded in [ADR-0006](../adr/0006-harness-participants-over-acp.md).

`@gambi/agents`, `apps/board`, and `apps/board-web` remain internal workspaces. The 0.7.0 workflow must not publish them.

## Post-merge release checklist

Do not run these steps from PR #81 or another feature branch.

1. Confirm PR #81 merged and refresh `main`:

   ```bash
   gh pr view 81 --json state,mergedAt,mergeCommit
   git fetch origin main
   git switch main
   git pull --ff-only
   ```

2. Validate the exact `main` commit that will be released:

   ```bash
   bun install --frozen-lockfile
   bun run check-types
   bun test packages/core
   bun test packages/sdk
   bun test packages/agents
   bun test packages/cli
   bun test apps/tui scripts/event.test.ts
   bun test apps/board/src/__tests__
   bun run --cwd packages/cli build
   bun run --cwd packages/sdk build
   bun run --cwd apps/docs build
   node ./packages/cli/dist/npm/gambi/bin/gambi join --help | rg -- '--harness'
   ```

3. Dispatch the existing workflow with a minor bump from `main`:

   ```bash
   gh workflow run release.yml --ref main -f bump=minor
   gambi_release_run_id=$(gh run list --workflow=release.yml --branch main --limit 1 --json databaseId --jq '.[0].databaseId')
   gh run watch "$gambi_release_run_id" --exit-status
   ```

   Confirm the workflow's `version` job calculated `0.7.0`. Do not edit any `package.json` version by hand.

4. Verify the npm package set and GitHub Release:

   ```bash
   npm view gambi@0.7.0 version
   npm view gambi-sdk@0.7.0 version
   npm view gambi-tui@0.7.0 version
   npm view gambi-linux-x64@0.7.0 version
   npm view gambi-linux-arm64@0.7.0 version
   npm view gambi-darwin-arm64@0.7.0 version
   npm view gambi-darwin-x64@0.7.0 version
   npm view gambi-windows-x64@0.7.0 version
   gh release view v0.7.0 --json tagName,isDraft,isPrerelease,assets,url
   ```

5. Install the published wrapper and verify the public flag:

   ```bash
   npm install -g gambi@0.7.0
   gambi --version
   gambi join --help | rg -- '--harness'
   ```

## Authentication note

Keep the current npm authentication configuration. Failed Trusted Publishing attempts around v0.3.2 ended with commit `8372798`, which restored `NODE_AUTH_TOKEN` after granular token access and 2FA bypass were configured for the packages. Issue #28 records the earlier v0.3.0 CI `404`. The granular token and workflow verification report are the current release design. This release is not an auth migration.
