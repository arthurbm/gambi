# Status do ACP (2026-08) e o que roubar do Gas Town

**Status:** pesquisa, 2026-08-22. Gerado por agente a partir de fontes primárias (GitHub via `gh api`, `npm view`, docs e blogs oficiais). Datas e versões são as do dia.
**Contexto:** [`harness-orchestration-options.md`](harness-orchestration-options.md) recomenda ACP (Agent Client Protocol) como camada uniforme entre o hub e os harnesses (OpenCode, Claude Code, Codex, Pi) rodando no PC de cada pessoa.
**Perguntas:** (1) o boato "o Zed está aposentando o ACP / a Anthropic não recomenda" procede? (2) o que é o Gas Town e o que vale copiar para um orquestrador de um dia?

## TL;DR

- **Boato "Zed aposentou o ACP": não procede.** Release `schema-v1.21.0` / `v1.7.0` em 2026-08-20, commits em 2026-08-22, governança conjunta Zed + JetBrains, e ACP continua sendo o único caminho para agentes externos no Zed. O que foi "deprecated" é embalagem: os pacotes npm `@zed-industries/*` (renomeados para `@agentclientprotocol/*`) e a instalação de agentes por extensão (substituída pelo ACP Registry).
- **Boato "Anthropic não recomenda ACP": procede parcialmente, e o problema não é o ACP.** A Anthropic nunca citou o ACP. O adapter `claude-agent-acp` é mantido pelo Zed, não pela Anthropic. O que existe de real: os termos do Claude Code proíbem terceiros de intermediar login de assinatura e mandam quem usa o Agent SDK usar API key; e em junho de 2026 a Anthropic tentou tirar o uso via SDK/apps de terceiros dos limites da assinatura, depois pausou. Isso atinge qualquer integração via Agent SDK (ACP, `@ai-sdk/harness-claude-code`, script próprio), não o protocolo.
- **O que muda na recomendação:** nada na escolha do ACP 1.x pinado. Registrar o risco de termos/billing no lado Claude Code e manter o desenho "cada pessoa roda seu binário no seu PC, o hub nunca vê token".
- **Gas Town** (Steve Yegge, Go, 17,7k stars) é um gerenciador de dezenas de sessões Claude Code em tmux + worktrees, com estado em Dolt/Beads. Vale copiar: hook por worker ("se tem trabalho no hook, rode"), mail tipado entre papéis, handoff = nota para si mesmo + restart, enum de estado do worker com heartbeat, redispatch com cooldown e escalação para humano após N falhas. Não copiar: Dolt/Beads, Formulas/Molecules, cadeia tripla de watchdogs, Refinery estilo Bors, o zoológico de papéis.

[zed.dev/docs/ai/external-agents](https://zed.dev/docs/ai/external-agents)

Anteriores: [JetBrains on ACP](https://zed.dev/blog/jetbrains-on-acp), [Codex is live in Zed](https://zed.dev/blog/codex-is-live-in-zed), landing [zed.dev/acp](https://zed.dev/acp).
- Código: `crates/agent_servers` e `crates/acp_thread` recebem commits ("acp: Poll the client connection future on a dedicated thread" #62259, 2026-08-15; "acp: Validate and surface more elicitation warnings" #61708, 2026-07-27). [commits](https://github.com/zed-industries/zed/commits/main/crates/agent_servers)

### Conclusão da pergunta 1

- "Zed está aposentando o ACP": **não procede.**
- "Anthropic não recomenda": **procede parcialmente** — não há posição sobre ACP; há restrição de termos sobre login de assinatura via terceiros e uma tentativa pausada de separar billing. Afeta Claude Code por qualquer caminho que use o Agent SDK.
- **Para a recomendação de ACP 1.x pinado:** mantém. Ajustes: (1) pinar `@agentclientprotocol/sdk@1.4.x` e negociar só v1 (`protocolVersion: 1`), ignorando v2 até sair do draft; (2) no participante Claude Code, deixar claro que é o binário/adapter da pessoa com a conta dela e que o hub nunca recebe token (já é o invariante `ParticipantAuthHeaders`); (3) documentar que, se a Anthropic retomar a separação de billing, o harness Claude Code passa a custar créditos do Agent SDK ou API key — OpenCode, Codex e Pi não têm esse risco; (4) preferir os pacotes `@agentclientprotocol/*`, nunca os `@zed-industries/*`.

## 2. Gas Town

**O que é.** "Multi-agent workspace manager" de Steve Yegge: CLI em Go (`gt`) que roda dezenas de sessões de Claude Code (também Codex/Copilot/Gemini/Cursor) em tmux, cada uma no seu git worktree, com o estado do trabalho persistido em **Beads** (`bd`, issue tracker dele sobre git/Dolt) para os agentes sobreviverem a crashes e resets de contexto. Anunciado em 2026-01-01 em ["Welcome to Gas Town"](https://steve-yegge.medium.com/welcome-to-gas-town-4f25ee16dd04); resumo em [yegge.ai/gastown](https://yegge.ai/gastown) ("Agents read and write the ledger; humans audit it").

**Repo e maturidade.** [github.com/gastownhall/gastown](https://github.com/gastownhall/gastown) (movido de `steveyegge/gastown`; `steveyegge/gas-town` não existe). Go, MIT, 17.715 stars, criado 2025-12-16, último push 2026-08-19, ~373 contributors, releases v1.0.0 (2026-04-03) → v1.2.1 (2026-06-06). Dependências pesadas: Go 1.26, Dolt SQL server, `bd` ≥ 0.57, sqlite3, ICU, tmux 3+ ([README](https://github.com/gastownhall/gastown#prerequisites)). A Kilo oferece versão hospedada ([The New Stack](https://thenewstack.io/steve-yegges-ai-agent-orchestration-project-gas-town-comes-to-the-cloud-and-brings-the-wasteland-with-it/)).

**Modelo de orquestração** (termos de [overview.md](https://github.com/gastownhall/gastown/blob/main/docs/overview.md) e [glossary.md](https://github.com/gastownhall/gastown/blob/main/docs/glossary.md)):
- *Papéis.* Um **Town** contém **Rigs** (um por repo). Na cidade: **Mayor** (coordenador singleton com quem o humano conversa), **Deacon** (daemon supervisor em ciclos de "Patrol"), **Dogs** (helpers efêmeros do Deacon; **Boot** checa o Deacon a cada 5 min). No rig: **Witness** (ciclo de vida dos workers), **Refinery** (merge queue), **Polecats** (workers: "persistent identity, ephemeral sessions"), **Crew** (clones longevos de humanos/agentes que fazem push direto na main).
- *Despacho.* Unidade de trabalho é um **Bead**; lote é um **Convoy**. `gt sling <bead> <rig>` pendura o bead no **Hook** do agente ("a special pinned Bead for each agent"). **GUPP**: "If there is work on your Hook, YOU MUST RUN IT" ([propulsion-principle.md](https://github.com/gastownhall/gastown/blob/main/docs/concepts/propulsion-principle.md)). Scheduler opcional limita concorrência ([scheduler.md](https://github.com/gastownhall/gastown/blob/main/docs/design/scheduler.md)). Workflows: **Formula** (TOML) → **Protomolecule** → **Molecule** (persistente) ou **Wisp** (efêmero) ([molecules.md](https://github.com/gastownhall/gastown/blob/main/docs/concepts/molecules.md)).
- *Sessões.* Cada papel é um pane tmux rodando Claude Code com `.claude/settings.json` específico via `--settings` (hooks: SessionStart → `gt prime`, PreCompact, UserPromptSubmit checa mail, Stop registra custo) ([HOOKS.md](https://github.com/gastownhall/gastown/blob/main/docs/HOOKS.md)). Reciclagem de sessão via `gt handoff` ("sends mail to self", o manager mata e reinicia) é "normal operation, not failure" ([polecat-lifecycle.md](https://github.com/gastownhall/gastown/blob/main/docs/concepts/polecat-lifecycle.md)). `gt nudge` injeta texto numa sessão; `gt seance` deixa a sessão nova consultar o `.events.jsonl` da anterior ([reference.md](https://github.com/gastownhall/gastown/blob/main/docs/reference.md)).
- *Humanos.* Falam com o Mayor; `gt mail send --human` chega ao "Overseer"; `gt escalate -s MEDIUM|HIGH|CRITICAL` cria bead de escalação roteado Deacon → Mayor → Overseer (email/SMS/Slack), re-escala se parado 4 h ([escalation.md](https://github.com/gastownhall/gastown/blob/main/docs/design/escalation.md)). Sem gate de code review humano por padrão: o Refinery mergeia sozinho.
- *Estado e falhas.* Tudo num Dolt SQL server por town (se cai, `bd` falha) ([architecture.md](https://github.com/gastownhall/gastown/blob/main/docs/design/architecture.md)); heartbeats em três stores ([heartbeats.md](https://github.com/gastownhall/gastown/blob/main/docs/concepts/heartbeats.md)). Estados de polecat: Working/Idle/Done/Stalled/Zombie; Witness detecta stall, reabre o bead e manda `RECOVERED_BEAD` ao Deacon, que faz `redispatch` com cooldown de 5 min e escala ao Mayor após 3 falhas ([mail-protocol.md](https://github.com/gastownhall/gastown/blob/main/docs/design/mail-protocol.md)).
- *Merge.* `gt done` faz push + MR; fluxo de mail `POLECAT_DONE` → Witness → `MERGE_READY` → Refinery → `MERGED` / `MERGE_FAILED` / `REWORK_REQUEST` (com instruções de rebase). Refinery é "Bors-style bisecting queue" ([README](https://github.com/gastownhall/gastown#refinery-)); epics podem usar integration branches ([integration-branches.md](https://github.com/gastownhall/gastown/blob/main/docs/concepts/integration-branches.md)).

**O que roubar para 1 orquestrador + N harnesses + humanos revisando, pronto em um dia:**
1. **Hook + GUPP.** Uma "tarefa atual" pinada por harness; ao abrir sessão, o harness lê e executa. Despachar = escrever no hook. No Gambi: a tool `dispatch` grava a tarefa no registro do participante e o `session/prompt` inicial é "você tem isso no hook".
2. **Mail tipado entre papéis.** Mensagens com subject fixo (`DONE`, `REVIEW_READY`, `REWORK_REQUEST`, `ESCALATE`) e corpo key:value. Cabe em JSON no túnel e vira log auditável de graça.
3. **Handoff = nota para si mesmo + restart.** Contexto cheio → o harness escreve resumo, a sessão morre, a nova lê o resumo. No ACP é `session/new` + prompt com a nota; não depender de `session/load`.
4. **Enum de estado + heartbeat.** `idle | working | done | stalled` reportado pelo harness, cruzado com a presença do túnel antes de declarar "travado".
5. **Redispatch com cooldown e contador.** Falhou → espera → redespacha em outro harness; após N falhas, escala para humano (`session/request_permission` ou mensagem na TUI).
6. **Rework loop em vez de merge automático.** Um revisor humano por tarefa; reprovou → `REWORK_REQUEST` com o motivo vira follow-up na mesma sessão ACP.

**O que não copiar:** Dolt + Beads + ICU/sqlite como store (dependência dura; um JSON/SQLite ou GitHub Issues dá a mesma trilha); Formulas → Molecules → Wisps (templating criado para conter 6k linhas/dia de wisps; um checklist em markdown no corpo da tarefa basta); cadeia tripla de watchdog e três stores de heartbeat (os próprios docs relatam falsos "stuck" por divergência); Refinery estilo Bors e integration branches (só faz sentido com 20-30 workers num repo); o zoológico Mayor/Deacon/Dogs/Crew/Witness (cada papel é uma sessão Claude gastando tokens para supervisionar — colapsar em orquestrador em código + harnesses + humanos); Wasteland/federação por DoltHub ([WASTELAND.md](https://github.com/gastownhall/gastown/blob/main/docs/WASTELAND.md)).
