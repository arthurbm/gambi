---
title: Crie um runtime de participante customizado
description: Use createParticipantSession() para rodar seu próprio processo de participante quando a CLI não basta.
---

A CLI `gambi participant join` cobre o caso comum: escolher um modelo, apontar para um hub e ficar online. Quando você precisa de mais controle, construa seu próprio runtime em cima de `createParticipantSession()`. Exemplos: embutir o participante num serviço de longa duração, adicionar lógica de shutdown customizada ou rodar vários participantes num mesmo processo.

Este guia mostra o runtime mínimo que se comporta como a CLI e, depois, as extensões mais comuns.

## Antes de começar

Você precisa de:

- um hub do Gambi acessível (`gambi hub serve`), na mesma minor do `gambi-sdk` que você instalar
- um código de sala existente (`gambi room create --name "Demo"`)
- um endpoint de provedor local compatível com OpenAI (Ollama, LM Studio, vLLM ou qualquer outro que sirva `/v1/models` e `/v1/chat/completions`)
- [Bun](https://bun.sh): a entrada `gambi-sdk/participant` só roda no Bun
- o `gambi-sdk` instalado

```bash
bun add gambi-sdk
```

## Passo 1: Entre na sala

`createParticipantSession()` faz tudo numa única chamada: testa quais APIs o seu endpoint fala, registra o participante, abre o túnel e resolve assim que o participante fica `online`.

```ts
import { createParticipantSession } from "gambi-sdk/participant";

const session = await createParticipantSession({
  hubUrl: "http://localhost:3000",
  roomCode: "ABC123",
  participantId: "worker-1",
  nickname: "worker-1",
  endpoint: "http://localhost:11434",
  model: "llama3",
});

console.log("joined as", session.participant.id);
```

Se a entrada falhar, a chamada rejeita com um `ParticipantError` e nada fica rodando. O `code` dele diz o motivo: `ROOM_NOT_FOUND`, `INVALID_PASSWORD`, `VERSION_MISMATCH` (o hub roda outra minor), `HUB_UNREACHABLE`, `TUNNEL_OPEN_FAILED` e mais alguns. Trate isso como erro de configuração e encerre.

A sessão não confere se o seu provedor serve o `model`. Para conferir antes de entrar, teste o provedor:

```ts
import { probeProvider } from "gambi-sdk/participant";

const probe = await probeProvider("http://localhost:11434");
if (!probe.models.includes("llama3")) {
  throw new Error("Pull the model first.");
}
```

## Passo 2: Acompanhe a sessão

Depois da entrada, o runtime cuida de si mesmo. Quando o túnel cai (o Wi-Fi pisca, o hub fica inacessível por um momento, o hub travou), ele espera 1 segundo, depois 2, 4 e assim por diante até 30, e se registra de novo com o mesmo participant ID. Apps que roteiam para ele pelo ID continuam com o mesmo alvo.

`onLifecycle` recebe cada etapa, em ordem:

```ts
const session = await createParticipantSession({
  // ...
  onLifecycle: (event) => {
    if (event.type === "reconnecting") {
      console.log(`tunnel lost (${event.reason}); retrying in ${event.delayMillis} ms`);
    }
  },
});
```

| Evento | Quando |
| --- | --- |
| `connected` | o túnel está aberto; `attempt` é `0` na entrada e, depois, a tentativa que o trouxe de volta |
| `reconnecting` | o túnel caiu e o runtime tenta de novo em `delayMillis` |
| `left` | o runtime terminou e não vai tentar de novo; é sempre o último evento |

`session.ended` resolve com o motivo do evento `left`. Ela nunca rejeita:

```ts
const { reason, error } = await session.ended;
```

| Motivo | Significado | Ação sugerida |
| --- | --- | --- |
| `"stopped"` | seu código chamou `leave()` ou `stop()` | encerre normalmente |
| `"refused"` | o hub recusou a volta; `error` traz o `name` e a `message` dele | em geral a sala sumiu, porque o hub reiniciou. Crie a sala de novo e inicie uma nova sessão |
| `"replaced"` | outro runtime entrou na sala com o mesmo participant ID, e o hub ficou com ele | não reinicie com o mesmo ID; dois runtimes não podem compartilhá-lo |
| `"removed"` | alguém removeu o participante pelo hub | a sessão terminou. Inicie outra se quiser voltar à sala |
| `"tunnelDropped"` | o túnel caiu e você passou `reconnect: false` | inicie uma nova sessão se quiser voltar |

Um participante que fica fora por mais de 60 segundos é removido da sala. O runtime não desiste depois disso: o próximo registro dele o traz de volta como um novo participante com o mesmo ID.

## Passo 3: Encerre de forma limpa

O SDK não instala handlers de sinal. Ligue `session.leave()` ao `SIGINT` e ao `SIGTERM` você mesmo. `leave()` tira o participante da sala e para o runtime. Ele nunca rejeita e desiste de um hub que não responde em 3 segundos (`leaveTimeoutMs`).

```ts
for (const signal of ["SIGINT", "SIGTERM"] as const) {
  process.on(signal, () => {
    void session.leave();
  });
}
```

`session.stop()` para o runtime sem avisar o hub. A sala mostra o participante como `offline` e o remove depois de 60 segundos, a menos que um runtime com o mesmo ID entre antes disso. Use quando você está prestes a reiniciar e quer voltar como o mesmo participante.

A sessão também funciona com `await using`, que chama `leave()`.

## Passo 4: Repasse a autenticação do provedor

Os `authHeaders` só são aplicados quando o runtime chama o endpoint do seu provedor. Eles nunca saem do runtime do participante. Use-os para chaves de API ou bearer tokens que o seu provedor exige.

```ts
const session = await createParticipantSession({
  hubUrl: "http://localhost:3000",
  roomCode: "ABC123",
  participantId: "worker-1",
  nickname: "worker-1",
  endpoint: "http://localhost:11434",
  model: "llama3",
  authHeaders: {
    Authorization: `Bearer ${process.env.PROVIDER_TOKEN}`,
  },
});
```

O hub nunca vê o `PROVIDER_TOKEN`.

## Passo 5: Customizações comuns

### Declare as especificações da máquina

A TUI mostra as especificações, e os eventos da sala as incluem. Passe-as quando você souber. Os campos são `cpu`, `gpu`, `ram` (GB) e `vram` (GB), todos opcionais:

```ts
await createParticipantSession({
  // ...
  specs: {
    cpu: "Apple M2 Pro",
    ram: 32,
    gpu: "Apple M2 Pro integrated",
  },
});
```

### Pule o probe

Sem `capabilities`, a sessão testa o seu endpoint para descobrir quais APIs compatíveis com OpenAI ele suporta. Passe-as para pular o probe:

```ts
await createParticipantSession({
  // ...
  capabilities: {
    openResponses: "supported",
    chatCompletions: "supported",
  },
});
```

### Entrando numa sala protegida por senha

```ts
await createParticipantSession({
  // ...
  password: process.env.ROOM_PASSWORD,
});
```

### Vendo os logs do runtime

O runtime nunca escreve no seu stdout. Passe `onLog` para receber as linhas de log dele:

```ts
await createParticipantSession({
  // ...
  onLog: (entry) => console.error(entry.level, entry.message),
});
```

### Rodando mais de um participante num processo

Chame `createParticipantSession()` uma vez por participante. Cada chamada retorna uma sessão independente, com túnel e identidade de participante próprios. Espere as promises `ended` delas em paralelo.

```ts
const sessions = await Promise.all([
  createParticipantSession({ /* worker-1 */ }),
  createParticipantSession({ /* worker-2 */ }),
]);

await Promise.all(sessions.map((session) => session.ended));
```

## Um runtime completo

Juntando tudo:

```ts
import { createParticipantSession } from "gambi-sdk/participant";

const session = await createParticipantSession({
  hubUrl: process.env.GAMBI_HUB ?? "http://localhost:3000",
  roomCode: "ABC123",
  participantId: "worker-1",
  nickname: "worker-1",
  endpoint: "http://localhost:11434",
  model: "llama3",
  ...(process.env.PROVIDER_TOKEN
    ? { authHeaders: { Authorization: `Bearer ${process.env.PROVIDER_TOKEN}` } }
    : {}),
  onLifecycle: (event) => console.log("[gambi]", event.type),
});

for (const signal of ["SIGINT", "SIGTERM"] as const) {
  process.on(signal, () => {
    void session.leave();
  });
}

const { reason, error } = await session.ended;
console.log("[gambi] session ended:", reason);
if (error) {
  console.error(error.name, error.message);
}
process.exit(reason === "stopped" ? 0 : 1);
```
